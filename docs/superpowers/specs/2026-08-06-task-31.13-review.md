# Task 31.13 — SPA: review flow

Parent spec: `2026-08-06-epic-31-architecture.md`. Web equivalent of the
interactive reviewer, on 31.6's review endpoints.

## Flow

- Enter from `#review` (or `#review/<id>` for single re-review, parity with
  `review --id`). Load the queue (`GET /api/review/queue`); single mode loads
  `GET /api/review/:id` only.
- One transaction at a time: `wc-review-card` (`@nigel/ui`) shows
  date/description/amount/account prominently; below it the decision form:
  category picker (searchable `wa-select`, income+expense grouped as the TUI
  groups them), optional vendor input, optional "create rule" toggle
  revealing a pattern input pre-filled with the description (the TUI's
  default), match-type select.
- Apply → `POST /api/review/:id/apply`; keep `{ transactionId, ruleId }` on a
  client-side history stack for back navigation.
- **Back** (button + Esc): pop the stack, `POST /api/review/:id/undo`
  `{ ruleId }`, and re-present that transaction (undo_review parity — the
  decision and any created rule are gone).
- **Skip** (button + Tab): advance leaving it flagged.
- Progress indicator "n of m" during; completion summary (reviewed, skipped,
  rules created) with links to register and dashboard.

## Notes

- The queue can change server-side mid-review (another tab); a 404 on apply
  advances with a toast rather than wedging the flow.
- Keyboard parity documented on-screen: Enter apply, Tab skip, Esc back.
- Rule pattern UX: show a live "this pattern would also match…" hint via
  `POST /api/rules/test` (debounced) — the API exists (31.6); it's the same
  assist the managers screen gets.
- New `@nigel/ui` pieces: `wc-review-card`, `wc-progress-dots` (or reuse
  wa-progress), each with previews (default, with-rule-open, summary) + axe.

## Tests

App-level with mock client: apply→back round-trip issues undo with the right
ruleId and re-presents the transaction; skip leaves flag untouched; summary
counts; single-id mode reviews exactly one; queue-404 advance. Component
previews + axe.
