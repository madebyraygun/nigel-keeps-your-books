# Task 31.9 — SPA scaffold: app shell, api client seam, embedded build

Parent spec: `2026-08-06-epic-31-architecture.md` — the SPA architecture,
Component-First workflow, and embedding sections are normative. This task
builds the whole `web/` workspace; screen tasks (31.10–31.17) only add screens
and `@nigel/ui` components.

## Deliverables

1. **`web/` npm workspace** — three packages per the architecture spec:
   - `@nigel/theme`: fork the *structure* of `~/Dev/boxcraft/main/packages/theme`
     (per-category Lit `css` token files composed into one `CSSResult`, plus
     the build-css script emitting a plain stylesheet). Replace the boxcraft
     brand values with nigel's identity (pastel gradient accents from
     `src/effects.rs`, mono font for money). Keep the `--wa-*` shadowing
     contract and the `::part()` global overrides pattern; nigel-specific
     tokens use `--nc-*`. Include boxcraft's theme-contract test style
     (string-match the cssText for required tokens).
   - `@nigel/ui`: preview harness (glob manifest + query-string router,
     port 9090) copied from `packages/ui/preview/`; `WcIconBase` + starter
     icons; the first components the shell needs: `wc-app-shell`,
     `wc-nav-sidebar`, `wc-toast` region with `dispatchNcToast` typed-event
     bus (boxcraft's `dispatchWcToast` incl. top-layer popover trick),
     `wc-confirm` (wa-dialog wrapper), `wc-money` (signed amount with
     mono font + income/expense color — the SPA's `money_span` equivalent),
     `wc-empty-state`, `wc-spinner`/loading. Each with `.preview.ts` + axe
     test. Web Awesome primitives cherry-picked per component.
   - `@nigel/app`: `index.html` + `main.ts` (theme css, ui registration, root
     element `nigel-app`), screen registry (`Map<ScreenId, ScreenDef>` +
     `location.hash` sync — the epic's departure from boxcraft's 3-place
     switch), `SignalWatcher` re-export seam (`mixins/signal-watcher.ts`),
     app store (status/locked/company signals via the ReadonlySignal pattern),
     and stub screens for: dashboard, register, review, import, reports, 
     accounts, categories, rules, reconcile, undo, settings, unlock.
2. **Api client seam** — `apps/app/src/api/`: `types.ts` (status/unlock +
   ping types now; grows per API task), `client.ts` (`interface ApiClient`,
   `FetchApiClient`), transport signals `appLocked`/`appUnauthorized`. The
   unlock gate itself is 31.10; the scaffold routes 423 → unlock stub screen.
3. **Vitest setup** in all three packages: node-default/jsdom-by-glob,
   `test-setup.ts` shims (ElementInternals, dialog, matchMedia if needed),
   axe in `@nigel/ui`. Guard tests: dependency-manifest walk (boxcraft's
   `dependency-manifest.test.ts` adapted) and an api-seam test (no `fetch(`
   outside `src/api/`).
4. **Embedded build**: vite `build.outDir` → `web/dist` (replacing 31.3's
   placeholder — keep a committed fallback index.html story so cargo builds
   without node; document the choice in web/README.md). `vite.config.ts` dev
   server 5173 with `/api` + `/auth` proxy → `127.0.0.1:5731`,
   `changeOrigin: true`; aliases + `"development"` export condition for
   `@nigel/ui` source consumption.
5. **CI**: extend the existing GitHub workflow — node setup, `npm ci`,
   `npm run build`, `npm test`, `npm run lint` in `web/`, ordered before
   cargo build/test so the embed picks up fresh dist.
6. **Docs**: CLAUDE.md (architecture + commands + structure sections),
   README (serve quick start), `web/README.md` (dev workflow).

## Acceptance shape

`nigel serve` opens the real SPA shell: sidebar navigation across all stub
screens, hash routing, toasts working, dark/light theme responding to system
preference. `npm test` green in all three packages; `cargo test` green;
preview harness renders every component state.
