# Task 31.5 — JSON API: read-only endpoints (reports and lists)

Parent spec: `2026-08-06-epic-31-architecture.md`. Handlers stay thin:
connection per request (spawn_blocking), call the data layer, serialize.

## Report endpoints (GET, all inside the locked guard)

| Route | Data fn | Params |
|---|---|---|
| `/api/reports/pnl` | `reports::get_pnl` | `year`, `month`, `from`+`to` |
| `/api/reports/expenses` | `get_expense_breakdown` | `year`, `month` |
| `/api/reports/tax` | `get_tax_summary` | `year` |
| `/api/reports/cashflow` | `get_cashflow` | `year`, `month` |
| `/api/reports/balance` | `get_balance` | — |
| `/api/reports/flagged` | `get_flagged` | — |
| `/api/reports/register` | `get_register` | `year`, `month`, `from`+`to`, `account` |
| `/api/reports/k1` | `get_k1_prep` | `year` |

- Param semantics match the CLI exactly: `month` is `YYYY-MM` (a bad string is
  400, unlike `parse_month_opt`'s silent None), `from`/`to` must be a pair
  (lone one → 400 with the same message the CLI uses), unknown `account` → 404.
- Each report response is wrapped as
  `{ granularity: "monthAndYear"|"yearOnly"|"none", report: {...} }` using the
  `DateGranularity` mapping 31.1 moved into `reports.rs` — the SPA (31.15)
  drives its date controls from this instead of hardcoding.

## List endpoints (GET)

- `/api/accounts` → `accounts::list_accounts` (`Vec<Account>`).
- `/api/categories` → `categories::list_categories` (active only,
  `Vec<CategoryRow>`); `/api/categories/choices` → `reviewer::get_categories`
  if the simpler shape earns its keep — otherwise skip and let the SPA use the
  main list.
- `/api/rules` → **new** `rules::list_rules(&Connection) -> Result<Vec<RuleRow>>`
  extracted per the epic contract: public `RuleRow { id, pattern, matchType,
  vendor: Option<String>, category, categoryId, priority, hitCount }` (the
  current `rules_manager::load_rules` is private, coalesces vendor to `""`,
  and swallows errors — the new fn propagates errors and keeps `Option`).
  `rules_manager.rs` switches to it.
- `/api/imports` → **new** `undo::list_imports(&Connection) ->
  Result<Vec<ImportListItem>>` (id, filename, accountName, importDate,
  transactionCount — the `get_last_import` query without `LIMIT 1`).
- `/api/csv-profiles` → new small query returning saved profile names from
  `csv_profiles` (name + column config; importer.rs owns the SQL).
