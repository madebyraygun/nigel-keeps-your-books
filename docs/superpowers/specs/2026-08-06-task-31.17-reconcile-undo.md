# Task 31.17 — SPA: reconcile and undo screens

Parent spec: `2026-08-06-epic-31-architecture.md`. Two small form screens on
31.6's endpoints.

## Reconcile (`#reconcile`)

- Form: account `wa-select`, month picker (`wa-input type=month` → `YYYY-MM`),
  statement balance input (currency-formatted, `wc-money`-consistent).
- Submit → `POST /api/reconcile`; result panel: reconciled ✓ (statement vs
  calculated, zero discrepancy) or discrepancy ✗ with the difference amount
  highlighted — mirroring the TUI reconcile_manager result copy.
- Below the form: prior reconciliations for the selected account
  (`GET /api/reconciliations?account=` — date, month, balances, status),
  refreshed after each submit.
- `no_transactions` 409 renders inline ("no transactions for that account and
  month"), unknown account 404 likewise.

## Undo (`#undo`)

- List recent imports (`GET /api/imports`): filename, account, import date,
  transaction count — newest first; supersets the TUI's last-import-only view.
- Selecting one → `wc-confirm` dialog restating the details ("Delete N
  transactions imported from <file>?") → `DELETE /api/imports/:id` → toast
  with deleted count, list refreshes.
- Empty state when no imports exist.

## Freshness (AC #3)

Dashboard and register refetch on screen enter (established pattern), so both
reflect reconcile/undo outcomes without extra wiring — add an app test proving
register data is refetched when navigating there after an undo.

## Tests

Mock-client: reconcile happy/discrepancy/409 paths render correctly and

freshness test above. Previews + axe: reconcile result panel (both variants),
