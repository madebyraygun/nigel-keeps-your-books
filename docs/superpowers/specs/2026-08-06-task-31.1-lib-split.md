# Task 31.1 — Restructure crate into lib + bin targets

Parent spec: `2026-08-06-epic-31-architecture.md`. No behavior change.

**Objective:** add `src/lib.rs` so the data layer is linkable from the future
server module, integration tests, and a later Tauri split. `main.rs` slims to
clap parsing + dispatch + the ratatui panic hook.

## Design

- `src/lib.rs` declares the existing top-level modules `pub`: `db`, `models`,
  `reports`, `reviewer`, `importer`, `categorizer`, `reconciler`, `migrations`,
  `settings`, `error`, `fmt`, `browser`, `tui`, `effects`, `pdf` (cfg pdf) —
  plus `pub mod cli` (the cli data-layer functions in `accounts.rs`,
  `categories.rs`, `undo.rs`, `backup.rs`, `password.rs` are needed by the API
  tasks; gating what's exposed inside `cli` is fine, but the data-layer
  functions must be reachable from the lib).
- `main.rs` drops all `mod` declarations and imports from the crate
  (`nigel::...`). Binary name stays `nigel` (implicit `[[bin]]` via
  `src/main.rs` is fine; add explicit `[lib] name = "nigel"` if needed).
- Move `DateGranularity` (and its per-report mapping) from
  `cli/report/view.rs` (`pub(crate)`, ratatui-entangled) into `reports.rs` as a
  plain `pub enum` — the one presentation-decoupling this task performs,
  because 31.5/31.15 need it and the epic contract assigns it here.
  `PeriodMode` and `date_params()` stay in the view.
- **Not** in scope: extracting rules/report-text data layers (31.5/31.6 own
  those), touching `prompt_password_if_needed` (stays; the server just never
  calls it), or any serde work (31.2).

## Watchpoints (from the codebase inventory)

- `main.rs:27` installs the panic hook — binary-side, keep it there.
- Inline `#[cfg(test)]` modules that mutate the `DB_PASSWORD` global note
  `--test-threads=1` (db.rs:475); moving modules must not break that note's
  accuracy.
- `excel_serial_to_date` is `#[cfg(any(feature = "gusto", test))]` — confirm
  cfg(test) still applies to the lib target's unit tests.
- Feature-gated modules (`pdf`, gusto parts of `importer`) must keep building
  in all four feature combinations.

## Verification

`cargo build`, `cargo test`, `cargo test --no-default-features`,
`cargo clippy --all-targets`, `cargo fmt --check`. The assert_cmd integration
tests (`tests/cli_dispatch.rs`) pass unchanged — identical CLI behavior is the
acceptance bar. Grep-check: no `ratatui`/`crossterm` types appear in any
signature exposed from `lib.rs` outside `cli/*_manager`, `browser`, `tui`,
`splash`, `goodbye`, `dashboard`.
