# Task 31.16 — SPA: accounts, categories, and rules managers

Parent spec: `2026-08-06-epic-31-architecture.md`. CRUD screens over 31.6's
endpoints, superset of the TUI managers (web reaches CLI parity: category
edit of all fields, rule add/edit, pattern test).

## Shared pattern

One `wc-manager-layout` (`@nigel/ui`): list table + "Add" button + row
actions (edit, delete), edit-in-dialog (`wa-dialog` via `wc-confirm`-style
wrapper or inline form panel — pick one pattern, use it for all three).
Guardrail 409s render as inline `wa-callout`-style feedback in the dialog,
mapped from the structured `details.reason` (`has_transactions` → "…has N
transactions", `has_active_rules` → …), not raw API messages (AC #4 wants
clear inline feedback; the codes make it translatable).

## Screens

- **Accounts** (`#accounts`): list (name, type, institution, last4,
  transaction count if cheap — else omit), add (name + type selector matching
  TUI types + optional institution/last4), rename, delete (confirm; blocked
  delete shows reason).
- **Categories** (`#categories`): list (name, type, taxLine, formLine),
  add/edit all four fields — type as income/expense radio, taxLine free text,
  formLine free text with helper text documenting the vocabulary
  (`1120S-1a`, `1120S-2`, `1120S-5`, `1120S-N`, `K-N`, `excluded`) and a
  datalist of those values; soft-delete with guardrail reasons.
- **Rules** (`#rules`): list (priority-sorted: pattern, matchType, category,
  vendor, priority, hits), add/edit (pattern, matchType select
  contains/starts_with/regex, category select by id, vendor, priority
  number), deactivate (confirm). **Live pattern test**: in the add/edit form,
  a debounced `POST /api/rules/test` preview panel showing matching
  descriptions + counts (parity with `rules test`), including the
  invalid-regex 400 rendered inline.

## Notes

- All three refetch their list after any mutation (no optimistic cache).
- Category select options come from `/api/categories`; deleting a category
  that a rules-form has selected is the server's guardrail problem, surfaced
  inline.
- Empty states with pointers ("No rules yet — create one from Review or
  here").

## Tests

Mock-client CRUD flows per screen incl. 409 rendering with each reason code;
rules test preview debounce + invalid-regex path; previews + axe for
`wc-manager-layout` states (list, empty, dialog-open, guardrail-error) and
the rules test panel.
