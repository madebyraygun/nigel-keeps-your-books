# Task 31.7 — JSON API: import pipeline (upload, preview, confirm)

Parent spec: `2026-08-06-epic-31-architecture.md`. Built on
`importer::import_file`, which is clean (`&Connection`, no printing) but takes
`&Path` — uploads must be spooled to disk.

## Flow (three steps, mirrors import_manager.rs's sequence)

1. `POST /api/imports/upload` — multipart (axum `Multipart`), one file. Spool
   to `<data_dir>/tmp/uploads/<uuid>-<sanitized-filename>` (0600, dir 0700).
   Enforce a size limit (`DefaultBodyLimit`, 25 MB) and an allowlist of
   extensions (.csv, .xlsx, .xls — same as the CLI accepts). Returns
   `{ uploadId, filename, size }`. Uploads expire: purge files older than 1h
   at serve startup and on each upload.
2. `POST /api/imports/preview` `{ uploadId, account, format?, mapping? }` —
   runs `import_file(conn, path, account, format_key, dry_run = true,
   inline_config)` where `mapping` is a `GenericCsvConfig` (Deserialize from
   31.2). Returns `ImportResult` (imported/skipped/malformed counts,
   duplicateFile flag, sample rows) plus the detected/effective format key —
   `import_file` must be extended (or a thin wrapper added) to report which
   `ImporterKind`/profile it resolved, since the CLI prints this but the
   struct doesn't carry it. No mutation (dry_run already skips snapshot,
   imports row, and inserts).
3. `POST /api/imports/confirm` — same body plus `{ saveProfile? }`. Sequence:
   pre-import snapshot via `backup::snapshot_with_password` (the injectable
   variant — pass `get_db_password()`) to `<data_dir>/snapshots/` with the
   same naming the CLI uses, then `import_file(dry_run = false)`, then
   `categorizer::categorize_transactions`, then `save_csv_profile` if
   requested. Returns `{ imported, skipped, malformed, categorized,
   stillFlagged, importId }` — `importId` needs `import_file` (or wrapper) to
   surface the created imports-row id for 31.14's "review these" link and
   31.17's undo. Delete the spooled upload on success.

## Error mapping

Unknown account 404; unknown format key / profile 400; duplicate file
(checksum) is **not** an error — it's `duplicateFile: true` with zero imports,
exactly as the CLI reports it; malformed-row counts likewise data, not errors.
Parse failures (unreadable file) 400 with the parser's message. Missing/expired
uploadId → 404 `upload_not_found`.

## Notes

- `import_file` signature changes (returning format key + import id) ripple to
  `cli/import.rs` and `import_manager.rs` — keep their output identical.
- Gusto feature: when built without `gusto`, format key `gusto_payroll` is 400
  with a clear message (same behavior as CLI resolution failing).
- Multipart brings a dep decision: axum's `multipart` feature — gate under the
  existing `serve` feature; no new top-level crate unless required.

## Tests

Integration: upload→preview→confirm happy path with a fixture BofA CSV
(reuse importer test fixtures), preview mutates nothing (row counts before ==
after), confirm creates snapshot file + imports row + categorizes, duplicate
re-confirm reports duplicateFile, generic CSV with inline mapping + 
saveProfile round-trip (`/api/csv-profiles` then shows it), oversize upload
rejected, expired uploadId 404, temp dir empty after confirm.
