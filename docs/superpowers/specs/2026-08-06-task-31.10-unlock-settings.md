# Task 31.10 — SPA: unlock and settings screens

Parent spec: `2026-08-06-epic-31-architecture.md`. Consumes 31.4's
status/unlock endpoints; settings needs small endpoint additions listed below
(they belong to this task because no API task covers settings — coordinate
with `docs/api.md`).

## Unlock screen

- Boot sequence: `nigel-app` fetches `/api/status` before anything else; when
  `locked`, the shell renders only the unlock screen (no sidebar, no data
  fetches — parity with the splash gate). Components: `wc-unlock-card`
  (`@nigel/ui`: brand mark, masked `wa-input type=password`, submit, error
  line, attempts-remaining text) with preview states (default, error,
  backoff-disabled).
- Wrong password: show message + `attemptsRemaining`; during `retryAfterMs`
  disable the form with a countdown. Success: refresh status, enter the app.
- Never store the password anywhere client-side.

## Settings screen (parity with settings_manager.rs + load)

Sections:
1. **Business name** — GET current from status/companyName; save via
   `PUT /api/settings/company-name` `{ name }` → `db::set_metadata`.
2. **Update check** — toggle `update_check`; `GET/PUT /api/settings/app`
   wrapping `settings::load_settings`/`save_settings` (only `updateCheck`
   editable from the web; `userName` display-only).
3. **Data directory** — display current; switch via
   `POST /api/settings/data-dir` `{ path }` mirroring `load` semantics
   (validate path contains nigel.db; rewrite settings.json). On success the
   server re-reads state and the SPA does a full reload (`location.reload()`)
   — the "full app-wide refresh" AC. Locked/encryption state re-evaluates on
   reload. Note: password global must be cleared on switch
   (`set_db_password(None)`) so an encrypted target DB shows the unlock gate.
4. **Password management** — parity with password_manager: set (unencrypted →
   encrypted), change, remove. Endpoints `POST /api/settings/password/set|
   change|remove` wrapping `cli/password.rs::encrypt_database/rekey_database/
   decrypt_database` (the clean `&Path` fns). These operate on the DB file —
   the server must ensure no open connections during the operation
   (spawn_blocking + these are single-shot calls; document). After set/change,
   update the process global so the session stays unlocked. Confirmation
   double-entry client-side; `wc-confirm` before remove.

All four sections' server work is small and lives in
`src/server/routes/settings.rs`; document each in `docs/api.md`.

## Tests

UI: unlock flow states (locked boot shows gate before any data call — assert
via a mock ApiClient recording call order), backoff countdown, settings forms
submit + optimistic/refresh behavior, axe on new components' preview states.
Server: settings endpoints round-trip on tempdir settings/DB; password
set→status shows encrypted; data-dir switch to encrypted DB → status locked.
