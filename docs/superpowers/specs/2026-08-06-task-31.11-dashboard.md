# Task 31.11 — SPA: dashboard screen

Parent spec: `2026-08-06-epic-31-architecture.md`. Mirrors the TUI home
screen (`cli/dashboard.rs`) using 31.5 data.

## Data

Parallel fetches on screen enter: `/api/reports/pnl?year=<current>` (YTD),
`/api/reports/balance` (account balances + ytdNetIncome),
`/api/reports/cashflow?year=<current>` (bar chart months),
`/api/reports/flagged` (count for the badge), `/api/status` (companyName,
update notice — 31.4's status gains `updateAvailable: Option<String>` fed by
`cli/update.rs::check_and_notify`'s data path if trivially exposable; if that
drags in network-on-startup concerns, the server does the existing 24h-cooldown
check in a background tokio task and status reports the cached result — small
server addition owned here, documented in docs/api.md).

## Components (`@nigel/ui`, each with preview + axe)

- `wc-stat-card` — label + big money value (uses `wc-money`), used for YTD
  income / expenses / net.
- `wc-balance-list` — account name/type/balance rows.
- `wc-bar-chart` — 12-month grouped income/expense bars, CSS-driven (no chart
  library; flex/grid bars with tooltips via `title`/wa-tooltip), tokens only.
- `wc-notice-bar` — the update-available banner (variant styling from tokens).
- Composition (`apps/app`): quick-nav uses the existing sidebar; a flagged
  badge chip on the review nav item + a call-to-action card linking `#review`
  when count > 0.

## Behavior

- Refresh action (button + `r` key alignment is unnecessary — web idiom: a
  refresh icon-button on the screen header) re-runs all fetches (AC #3).
- Empty DB: friendly `wc-empty-state` pointing at import.
- Loading: skeleton or spinner per card; errors surface via toast + inline
  retry, not blank panels.

## Tests

Store/composition tests with a mock ApiClient (fetch fan-out, badge count,
refresh re-fetch); component previews cover loading/empty/populated/negative
values; axe green; bar chart renders 12 buckets from a cashflow fixture and
handles a short first year.
