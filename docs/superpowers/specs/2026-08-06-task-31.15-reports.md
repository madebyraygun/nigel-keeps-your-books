# Task 31.15 — SPA: report views

Parent spec: `2026-08-06-epic-31-architecture.md`. All eight reports on
31.5's endpoints with 31.8's export downloads. Figures must match the CLI
text output for the same period — same data functions guarantee it; tests
assert it.

## Structure

- `#reports` landing lists the eight; `#reports/<name>` renders one.
- `wc-period-nav` (`@nigel/ui`; shared with 31.12 — whichever task lands
  first owns it): ◀/▶ period paging + month/year granularity toggle, driven
  by the `granularity` field each report response carries (monthAndYear:
  both paging and toggle; yearOnly: year paging only; none: hidden). Default
  period = current year, matching CLI defaults.
- Per-report rendering composes existing primitives (`wc-money`, tables).
  Report-specific components only where structure demands:
  - pnl: income/expense sections + totals + net.
  - expenses: category table + top-vendors table.
  - tax: tax-line table.
  - cashflow: month table + reuse `wc-bar-chart` (31.11).
  - balance: reuse `wc-balance-list` + ytd net income.
  - flagged: simple table, rows linking into `#review/<id>`.
  - register: read-only `wc-register-table` (no editing affordances —
    browse/edit lives at `#register`), plus account filter.
  - k1: worksheet layout mirroring the text report — gross receipts, COGS,
    gross profit, deduction lines, Schedule K items, other-deductions table
    with the 50% meals note, **needs-mapping section** and **auto-mapped
    note** (AC #4), validation block (uncategorized count, comp/dist ratio).
- Export buttons per report: PDF and Text, hitting `/api/exports/<name>`
  with the current period params — plain `<a download>` links so the browser
  handles the stream; PDF button hidden/disabled with explanation when the
  server reports `feature_disabled` (probe once via status or handle 501 with
  a toast).

## Print stylesheet

`@media print` in `@nigel/theme`'s global layer: hide shell chrome (sidebar,
toolbars, buttons), black-on-white tokens, sensible page margins. "Pages
print cleanly" AC — verify via vitest snapshot of the print CSS presence plus
manual check documented in the task notes.

## Tests

Parity test (the load-bearing one): seed a DB, for each report compare
API-rendered figures against `reports::get_*` output directly (the SPA test
uses fixture JSON captured from the same seed — document the fixture
generation script in web/README.md). Period-nav logic unit tests per
granularity. Previews + axe for `wc-period-nav` and the k1 needs-mapping
state. Flagged→review deep link.
